# 거울 속의 손님 금기 정의

이 문서는 `거울 속의 손님`의 금기인 `같은 질문 반복 금지`를 서버에서 어떻게 판정할지 정의한다.

## 결정

`같은 질문 반복`은 정보 대상 반복으로 정의한다.

## 정보 대상

프론트는 플레이어가 확인하려는 정보 대상을 선택할 수 있게 한다.

서버는 행동 제출 시 `info_target_key`를 받아 저장한다.

승인된 정보 대상:

| info_target_key | 의미 |
|---|---|
| `mirror_surface` | 거울 표면 |
| `mirror_back` | 깨진 거울 뒷면 |
| `missing_child_voice` | 사라진 아이의 목소리 |
| `forgotten_room` | 잊어버린 방 번호 |
| `self_reflection` | 플레이어의 비친 얼굴 |

## 금기 위반 판정

같은 정보 대상을 연속으로 조사하면 `거울 속의 손님`의 금기 위반으로 판정한다.

MVP에서는 직전 정보 대상과 이번 턴 정보 대상만 비교한다.

최근 N턴 내 반복 판정은 사용하지 않는다.

금기 위반이 발생하면 항상 거짓 단서 생성 후보를 만든다.

화면 표현은 질문처럼 만들 수 있지만, 서버 판정은 정보 대상 key 기반으로 한다.

## 비사용 판정

MVP에서는 아래 방식으로 금기 위반을 결정하지 않는다.

- 자유 텍스트 질문 유사도
- LLM 판정
- embedding 유사도
- 단순 행동 반복

## API 영향

행동 제출 요청은 `info_target_key`를 optional field로 받을 수 있다.

단, 정보 행동은 `info_target_key`가 필수다.

초기 기준의 정보 행동:

- `insight`
- `contract`
- `seal`

비정보 행동은 `info_target_key`가 없어도 제출할 수 있다.

비정보 행동에 `info_target_key`가 포함되면 서버는 저장할 수 있지만, 해당 행동의 룰 효과에 사용할지는 행동별 정책을 따른다.

예시:

```json
{
  "action_code": "insight",
  "info_target_key": "mirror_back",
  "client_nonce": "uuid-generated-by-frontend"
}
```

## 확정된 제외 조건

- 최근 N턴 내 반복 판정은 MVP에서 사용하지 않는다.
- 금기 위반 여부를 확률로 결정하지 않는다.
- 금기 위반 후 거짓 단서 생성 후보 여부를 확률로 결정하지 않는다.
