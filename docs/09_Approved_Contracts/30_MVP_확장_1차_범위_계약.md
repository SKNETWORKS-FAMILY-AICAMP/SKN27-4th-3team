# MVP 확장 1차 범위 계약

이 문서는 2026-06-10 확정된 MVP 확장 1차 작업의 포함/제외 범위를 고정한다.

기존 승인 계약 01-29번은 계속 유효하다. 이 문서는 아래 항목에 대해서만 후속 구현 범위를 보강한다.

## 결정

추천 확정안 A를 1차 확장 기준으로 사용한다.

1차 확장은 계약과 검증이 명확한 항목부터 진행한다. 운영 자동화, 서버 시작 자동 RAG ingest, 실제 production 배포 완료 증거는 별도 조건이 충족되기 전까지 1차 구현 범위에 포함하지 않는다.

## 1차 포함 항목

| 항목 | 1차 기준 |
|---|---|
| strict JSON 산출물 정리 | `api-spec/pilot-mvp-api.official.json`이 PowerShell `ConvertFrom-Json`과 Python `json.load` 기준으로 모두 파싱되어야 한다. |
| official API 원본/산출물 동기화 | `api-spec/pilot-mvp-api.official.jsonc`와 strict JSON 생성본은 의미적으로 같은 승인 schema를 담아야 한다. |
| password reset backend endpoint | 구현 전 별도 API/schema 계약을 먼저 추가한다. 구현은 그 계약에 한정한다. |
| RAG ingest/search API | 관리자 또는 명시적 실행자가 호출하는 수동 ingest/search 범위로만 진행한다. |
| LLM provider 검증 모드 | 기본 fallback/disabled 동작은 유지하고, 운영 검증용 강제 모드만 추가한다. |

## 1차 제외 항목

| 항목 | 제외 기준 |
|---|---|
| RAG 서버 시작 자동 ingest | 서버 startup, migration, app import, ASGI/WSGI boot 과정에서 자동 ingest를 실행하지 않는다. |
| production CI/CD 자동 배포 | GitHub Actions, CD runner, 자동 SSH 배포, 자동 migration 실행은 별도 운영 계약 전까지 제외한다. |
| image registry push | GHCR, Docker Hub, private registry push/pull 흐름은 1차 범위에서 제외한다. |
| 자동 백업 | 주기적 `pg_dump`, object storage 업로드, retention 정책 자동화는 별도 운영 계약 전까지 제외한다. |
| monitoring/alerting platform | Prometheus, Grafana, Sentry, uptime monitor, Slack/Discord/email alerting은 1차 범위에서 제외한다. |
| 실제 production 배포 완료 증거 | VM, domain, registry, secret, DNS, SSH 접근 권한이 제공되기 전까지는 배포 준비 검증만 수행한다. |
| LLM 판정 권위 확대 | LLM은 룰, 승패, 인증, 권한, 공식 단서, 진명 조각, 거짓 단서, 괴이 행동 선택을 결정하지 않는다. |

## strict JSON 정리 기준

`api-spec/pilot-mvp-api.official.json`은 도구가 읽는 strict JSON 산출물이다.

검증 기준은 아래와 같다.

- PowerShell `ConvertFrom-Json`으로 파싱된다.
- Python `json.load`로 파싱된다.
- JSONC 원본에만 허용되는 주석, trailing comma, 비표준 문자열이 strict JSON 산출물에 남지 않는다.
- strict JSON 수정 중 endpoint 의미, response envelope, error code를 임의 변경하지 않는다.

schema 의미 변경이 필요한 경우 이 문서가 아니라 별도 API 계약을 먼저 추가한다.

## password reset 구현 게이트

password reset은 보안 민감 기능이므로 구현 전에 별도 API/schema 계약을 추가해야 한다.

그 계약에는 최소 아래 항목이 있어야 한다.

- 요청 endpoint와 확인 endpoint
- 요청/응답 envelope
- 토큰 TTL
- 토큰 1회성 사용 정책
- 사용자 존재 여부를 노출하지 않는 응답 정책
- rate limit 또는 남용 방지 정책
- password reset token 원문 저장 금지
- SecurityEvent 기록 범위
- CSRF 적용 여부
- 이메일 전송 provider가 없을 때의 local/dev 처리 방식

위 항목이 확정되기 전에는 password reset runtime을 구현하지 않는다.

## RAG ingest/search 구현 게이트

RAG는 1차에서 수동 ingest와 search API까지만 확장한다.

수동 ingest 기준은 아래와 같다.

- 명시적 명령 또는 관리자용 API 호출로만 실행한다.
- 서버 시작, import, migration, health check 중에는 실행하지 않는다.
- ingest 대상은 기존 RAG 승인 계약의 allowlist를 따른다.
- ingest 결과는 룰, 승패, 인증, 권한, 공식 단서, 진명 조각, 거짓 단서, 괴이 행동 선택을 바꾸지 않는다.
- 실패 시 게임 진행 자체를 막지 않는다.

search API 기준은 아래와 같다.

- 검색 결과는 LLM context 보조 또는 운영 확인용 근거로만 사용한다.
- query log에는 query, caller, document/chunk reference, score, threshold, top_k, created_at을 남긴다.
- 검색 결과 payload는 공식 문서 경로와 chunk reference를 포함해야 한다.

## LLM provider 검증 모드 기준

기본 런타임은 기존 [[09_Approved_Contracts/25_LLM_Runtime_통합_계약]]의 fallback/disabled 정책을 유지한다.

운영 검증용 강제 모드는 아래 기준을 따른다.

- `LLM_REQUIRED` 기본값은 `false`다.
- `LLM_REQUIRED=true`일 때 API key 누락, provider 호출 실패, timeout, provider 응답 형식 오류는 health/smoke 검증 실패로 처리한다.
- 강제 모드는 배포 검증과 운영 점검을 위한 것이며, LLM이 게임 판정 권위를 갖는다는 뜻이 아니다.
- provider secret, raw prompt, raw response, Authorization header는 로그에 저장하지 않는다.

## production 운영 자동화 분리 기준

CI/CD, image registry push, 자동 백업, monitoring/alerting은 1차 구현에서 제외한다.

해당 항목을 진행하려면 별도 운영 계약에서 최소 아래 값을 확정해야 한다.

- repository hosting과 CI runner
- image registry 종류와 image tag 규칙
- secret 주입 방식
- migration 실행 정책
- backup 대상, 저장 위치, retention, 복구 검증 방식
- monitoring 지표, alert 조건, 알림 채널
- production 접근 권한과 배포 승인자

## 구현 순서

1. strict JSON 산출물을 먼저 정리한다.
2. password reset API/schema 계약을 추가한다.
3. RAG 수동 ingest/search API 계약을 추가한다.
4. LLM provider 강제 검증 모드 계약을 필요한 범위만 세분화한다.
5. 각 계약이 승인된 뒤 구현과 테스트를 진행한다.

## 충돌 해결 기준

이 문서는 1차 확장 범위를 정하는 문서다.

기존 계약과 충돌할 경우 아래 기준을 따른다.

- RAG 서버 시작 자동 ingest 제외는 기존 [[09_Approved_Contracts/25_LLM_Runtime_통합_계약]], [[09_Approved_Contracts/28_Production_배포_계약]]의 제외 기준을 유지한다.
- production CI/CD, registry push, backup, monitoring 제외는 기존 [[09_Approved_Contracts/28_Production_배포_계약]]의 제외 기준을 유지한다.
- LLM fallback/disabled 기본 동작은 기존 [[09_Approved_Contracts/25_LLM_Runtime_통합_계약]]을 유지한다.
- password reset과 RAG API endpoint는 기존 official API schema에 없으므로 별도 API/schema 계약 없이는 구현하지 않는다.
