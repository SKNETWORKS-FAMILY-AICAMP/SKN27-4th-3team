# 거짓 단서 생성 기준

이 문서는 거짓 단서 생성 방식에 대한 승인된 기준이다.

## 결정

거짓 단서는 속임수 결과와 괴이별 금기 위반으로 생성한다.

## 생성 후보

거짓 단서 생성 후보는 아래 상황에서 발생한다.

| 경로 | 설명 |
|---|---|
| 공통 룰: 속임수 | `속임수`가 성공하거나 `간파`가 속임수 판별에 실패하면 거짓 단서 생성 후보가 된다. |
| 괴이별 금기: 거울 속의 손님 | `같은 질문 반복 금지` 금기를 위반하면 거짓 단서 생성 후보가 된다. |

`거울 속의 손님`은 MVP에서 확률 기반 거짓 단서 생성을 사용하지 않는다.

금기 위반이 발생하면 항상 거짓 단서 생성 후보를 만든다.

## 거울 속의 손님 거짓 단서 선택 규칙

`거울 속의 손님`의 거짓 단서는 이번 턴의 `info_target_key`, 금기 위반 여부, 속임수 성공 여부를 기준으로 선택한다.

| 거짓 단서 | 생성 후보 조건 | 관련 정보 대상 |
|---|---|---|
| `거울을 깨면 끝난다.` | `mirror_surface` 또는 `mirror_back`을 연속 조사해 금기 위반이 발생하거나, 해당 정보 대상에서 `속임수`가 성공한 경우 | `mirror_surface`, `mirror_back` |
| `불을 끄면 안전하다.` | `missing_child_voice`를 연속 조사해 금기 위반이 발생하거나, 해당 정보 대상에서 `속임수`가 성공한 경우 | `missing_child_voice` |
| `이름을 부르면 괴이가 약해진다.` | 진명 조각을 2개 이상 보유한 뒤 `forgotten_room` 또는 `self_reflection`에서 금기 위반이 발생하거나 `속임수`가 성공한 경우 | `forgotten_room`, `self_reflection` |

## 중복 및 최대 보유

- 같은 거짓 단서는 중복 보유하지 않는다.
- 거짓 단서는 최대 3개까지 보유한다.
- 이미 보유 중인 거짓 단서가 다시 생성 후보가 되면 새 단서를 추가하지 않는다.
- 거짓 단서 3개를 모두 보유 중이면 새 거짓 단서를 추가하지 않는다.

## 서버 추적 필요 상태

`거울 속의 손님`의 금기를 룰로 사용하려면 서버가 아래 상태를 추적해야 한다.

- 이번 턴에 플레이어가 확인하려 한 정보 대상
- 직전 정보 대상
- 같은 정보 대상 연속 반복 여부
- 금기 위반 발생 턴
- 거짓 단서 생성 경로
- 금기 위반으로 생성된 거짓 단서 ID
- 현재 보유 중인 거짓 단서 ID 목록

## 서버 권위

최종 거짓 단서 생성, 공개, 제거 여부는 서버가 결정한다.

프론트는 단서가 거짓인지 임의로 확정하지 않는다.

`간파`가 속임수 판별에 성공하면 서버는 해당 속임수 또는 정보 대상과 연결된 거짓 단서를 거짓으로 공개하고 제거 또는 무효화한다.

## 프론트 표시 기준

- 거짓 단서는 처음부터 거짓이라고 표시하지 않는다.
- 서버가 거짓으로 공개한 뒤에만 거짓 단서로 표시한다.
- 금기 위반이 발생했더라도 서버 응답 전에는 거짓 단서 생성을 확정 표시하지 않는다.

## 확정된 제외 조건

- 최근 N턴 내 반복 판정은 MVP에서 사용하지 않는다.
- 자유 텍스트 질문 유사도, LLM 판정, embedding 유사도는 거짓 단서 trigger 판정에 사용하지 않는다.
- 확률 기반 거짓 단서 생성은 MVP에서 사용하지 않는다.
