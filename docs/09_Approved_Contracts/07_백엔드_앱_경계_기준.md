# 백엔드 앱 경계 기준

이 문서는 MVP 백엔드 앱 경계에 대한 승인된 기준이다.

## 결정

기존 문서상 앱 경계를 유지한다.

## MVP 우선 앱

| 앱 | 책임 |
|---|---|
| `accounts` | 회원가입, 로그인, 로그아웃, 토큰 갱신, 인증 이벤트 |
| `profiles` | 닉네임, 전적 요약, 스타일 요약 |
| `game_rules` | 행동, 자원, 상성, 승패 조건의 결정적 규칙 |
| `matches` | 매치, 참가자, 턴, 행동 제출, 결과 저장 |
| `story` | AI 스토리 사건, 괴이, 단서, 금기, 브리핑 |
| `ai_profile` | 행동 이벤트 저장, 스타일 지표 계산 |
| `retrieval` | RAG 문서, 청크, embedding, 검색, query log |

## 물리 폴더 기준

백엔드 앱은 `backend/apps/` 아래에 둔다.

```text
backend/
  config/
  apps/
    accounts/
    profiles/
    game_rules/
    matches/
    story/
    ai_profile/
    retrieval/
    llm/
    realtime/
    knowledge/
  tests/
```

프로젝트 최상위 폴더 구조는 [[09_Approved_Contracts/23_프로젝트_폴더_구조_계약]]을 따른다.

## 확장 경계

| 앱 | 초기 처리 |
|---|---|
| `realtime` | 1차 MVP 구현에서는 제외하되 future PvP 경계로 보존 |
| `llm` | 경계는 보존하되 판정 이후 요약부터 검토 |
| `knowledge` | 후순위 KAG 확장으로 보존 |

## 적용 제약

- `game_rules`는 공통 룰 계산을 담당한다.
- `story`는 괴이별 조건, 금기, 사건 데이터를 담당한다.
- `matches`는 매치/턴/제출/결과 저장을 담당한다.
- `matches`는 AI 스토리 전용으로 좁히지 않고 PvP 확장을 막지 않는다.
- LLM/RAG/KAG는 MVP 핵심 판정 경로에 직접 관여하지 않는다.
- `retrieval`은 구현 준비 범위에 포함하지만, 검색 결과로 룰/승패/인증/단서/괴이 행동 선택을 바꾸지 않는다.
- 상세 구현 기준은 [[09_Approved_Contracts/17_백엔드_RAG_AI_Profile_구현_계약]]을 따른다.
- PvP 구조 보존 기준은 [[09_Approved_Contracts/19_PvP_확정_후속_및_구조_보존_계약]]을 따른다.
- 프로젝트 폴더 구조 기준은 [[09_Approved_Contracts/23_프로젝트_폴더_구조_계약]]을 따른다.
