# 승인본 목차

이 폴더는 사용자가 명시적으로 승인한 프론트엔드/백엔드/스토리/LLM/RAG 공통 기준만 담는다.

검토 중인 문서는 [[08_Implementation_Contracts/00_공통_계약_목차]]를 본다.

## 승인된 운영 결정

- D-001: 검토안과 승인본을 분리한다.
- D-010: 프론트팀에는 큰 톤만 제공하되 최소 금지선을 둔다.
- D-011: 오너는 세계관 큰 틀, 첫 스토리 핵심 구조, 기술 계약의 최종 기준을 정하고, 프론트팀은 승인된 기준 안에서 화면 흐름과 표현을 설계한다.
- D-020: 사람이 첫 괴이 기준 문장을 작성하고, LLM은 판정 이후 변형/요약만 만든다.
- D-030: 진명 조각은 행동 상성 결과와 괴이별 조건을 함께 보고 획득한다.
- D-040: 거짓 단서는 속임수 결과와 괴이별 금기 위반으로 생성한다.
- D-100: API 명세는 JSONC 원본과 strict JSON 생성본을 함께 관리한다.
- D-110: API 응답은 `{ data, meta }` / `{ error, meta }` 형태로 통일한다.
- D-120: access token과 refresh token을 모두 HttpOnly cookie로 전달한다.
- D-130: 모든 state-changing endpoint에 CSRF를 적용한다.
- D-200: 기존 문서상 백엔드 앱 경계를 유지한다.
- D-300: LLM은 판정 이후 요약부터 사용한다.
- D-310: RAG는 MVP 핵심 흐름이 RAG 없이 완주 가능해야 한다는 제약을 유지한다.
- D-320: RAG는 `retrieval` 앱 구현 준비 범위에 포함하되, 룰/승패/인증/단서/괴이 행동 선택 권위에는 관여하지 않는다.
- D-400: `거울 속의 손님`의 같은 질문 반복은 정보 대상 반복으로 정의한다.
- D-401: `info_target_key`는 전체 행동 제출에서 선택값이지만 정보 행동에서는 필수다.
- D-402: `거울 속의 손님`의 MVP 정보 대상은 5개로 둔다.
- D-403: `거울 속의 손님`의 금기는 직전 정보 대상과 같은 `info_target_key`를 다시 조사한 경우에만 위반으로 판정한다.
- D-404: `거울 속의 손님`의 거짓 단서 trigger condition은 정보 대상 기반의 결정적 생성 규칙을 따른다.
- D-405: `거울 속의 손님`의 괴이 행동 정책은 결정적 가중치 기반 보정 버전을 따른다.
- D-500: 백엔드, RAG, AI Profile의 구현 준비 기준은 [[09_Approved_Contracts/17_백엔드_RAG_AI_Profile_구현_계약]]을 따른다.
- D-600: 전체 7x7 상성표, `간파` vs `침묵` 후보 2개 생성, 최소 상태 규칙, 동시 승패 우선순위는 A안 결정적 완성표 버전을 따른다.
- D-700: PvP 모드는 없다. 기존 PvP 확정 후속 핵심 기능과 PvP-ready 구조 보존 전제는 폐기한다.
- D-800: Django Auth 보안은 PvP 전제가 아니라 일반 웹 서비스 보안 기준으로 보수적으로 유지한다. refresh token family, reuse 감지, CSRF rotation, token 저장 금지, 보안 이벤트 로그를 필수로 둔다.
- D-900: 1차 MVP AI 스토리 시간초과는 브라우저 종료/네트워크 끊김 감지가 아니라 서버 `deadline_at` 기준으로 판정한다.
- D-910: API 상세 schema는 A안인 구현 직전용 최소 완성 schema를 사용한다. 공식 구현 기준은 `api-spec/pilot-mvp-api.official.jsonc`와 strict JSON 생성본이다.
- D-920: 프로젝트 폴더 구조는 Monorepo + 팀별 경계 분리 구조를 사용한다. `backend/`, `frontend/`, `llm/`, `api-spec/`, `docs/`, `tools/`, `output/`, `ops/`를 최상위 기준으로 둔다.
- D-930: Dockerfile 기반 백엔드 이미지 빌드와 Django 배포 준비는 [[09_Approved_Contracts/24_Dockerfile_이미지_빌드_배포_준비_계약]]의 결정 타이밍과 구현 게이트를 따른다.
- D-940: LLM runtime은 결과 요약, 턴 연출 문구, 결전 대화만 담당한다. `Turn.started_at`, `llm_generations`, `duel_dialogues`, refresh cookie path 확대 기준은 [[09_Approved_Contracts/25_LLM_Runtime_통합_계약]]을 따른다.
- D-950: `무명(無名)의 저주`는 `nameless_curse` 별도 사건으로 둔다. 정보 대상, 진명 조각, 거짓 단서, 피티 공식화 기준은 [[09_Approved_Contracts/26_무명의_저주_사건_계약]]을 따른다.
- D-960: 플레이어 표시 이름, 사건별 결전 가능 조건, `nameless_curse` 결전 LLM payload, RAG source plan은 [[09_Approved_Contracts/27_플레이어_이름_무명의_저주_결전_RAG_계약]]을 따른다.

## 아직 승인되지 않은 문서

- 현재 첫 괴이 기준 문서에서 남은 오너 결정은 없다.
- 프론트엔드 구현과 LLM generation 구현을 제외한 백엔드/API 구현 전 남은 오너 결정은 없다.
- production 배포 구현값은 아직 승인되지 않았다. 배포 구현 전 필요한 결정 항목은 [[09_Approved_Contracts/24_Dockerfile_이미지_빌드_배포_준비_계약]]의 Gate F에서 별도 계약으로 확정한다.
- PvP 관련 기존 후속 설계는 더 이상 승인된 구현 방향이 아니다. 현재 기준은 [[09_Approved_Contracts/19_PvP_미사용_및_구조_정리_계약]]의 PvP 미사용 결정이다.
