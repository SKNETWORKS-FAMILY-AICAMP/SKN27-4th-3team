# AI 스토리 시간초과 판정 계약

이 문서는 1차 MVP AI 스토리에서 브라우저 종료, 네트워크 끊김, 턴 제한 시간 만료를 어떻게 판정하는지에 대한 승인 기준이다.

## 결정

A안인 서버 `deadline_at` 기준 시간초과를 사용한다.

브라우저 종료 또는 네트워크 끊김 자체는 즉시 시간초과로 처리하지 않는다.

서버 기준 시각이 해당 턴의 `deadline_at`을 지났고, 유효한 플레이어 행동 제출이 없으면 시간초과로 처리한다.

## 적용 범위

- 1차 MVP AI 스토리 매치
- `거울 속의 손님` 사건
- 턴 행동 제출
- 시간초과 누적 횟수
- 재접속 후 최신 매치 상태 조회

PvP의 reconnect, grace time, heartbeat, WebSocket 기반 연결 감지는 1차 MVP 구현 범위에서 제외한다.

## 판정 기준

| 상황 | 판정 |
|---|---|
| 브라우저 종료 | 즉시 시간초과 처리하지 않는다. |
| 네트워크 끊김 | 즉시 시간초과 처리하지 않는다. |
| `deadline_at` 이전 유효 제출 | 정상 행동 제출로 처리한다. |
| `deadline_at` 이후 제출 | 제출을 유효 행동으로 반영하지 않는다. |
| `deadline_at`까지 제출 없음 | 시간초과로 처리한다. |
| 재접속 | `GET /api/v1/matches/{match_id}`로 최신 서버 상태를 조회한다. |

시간초과 판정의 기준 시각은 클라이언트 시각이 아니라 서버 시각이다.

## 시간초과 효과

시간초과가 발생하면 플레이어 기본 행동은 `침묵`이다.

시간초과가 발생한 턴은 플레이어 누적 시간초과 수를 1 증가시킨다.

1차 MVP AI 스토리의 반복 시간초과 효과는 [[02_Game_Rules/06_시간초과_규칙]]을 따른다.

`거울 속의 손님`에서 누적 시간초과가 3회 이상이면 괴이 행동은 [[09_Approved_Contracts/16_거울_속의_손님_괴이_행동_정책]]의 강한 패턴을 따른다.

## 서버 저장 기준

서버는 최소 아래 상태를 추적할 수 있어야 한다.

| 항목 | 기준 |
|---|---|
| 턴 마감 시각 | `turns.deadline_at` |
| 턴 해결 시각 | `turns.resolved_at` |
| 턴 상태 | 시간초과로 resolve됐는지 구분 가능해야 한다. |
| 행동 제출 | 유효 제출만 `action_submissions`에 반영한다. |
| 시간초과 누적 | participant 기준으로 추적한다. |

시간초과로 resolve된 턴의 결과와 공개 로그도 일반 턴 결과처럼 `turn_results`에 저장한다.

## 프론트 기준

프론트는 브라우저 종료나 네트워크 끊김을 자체적으로 패배, 항복, 시간초과로 확정하지 않는다.

프론트는 서버가 내려준 `deadline_at`을 기준으로 카운트다운을 표시할 수 있지만, 최종 판정은 서버 응답을 따른다.

재접속 또는 새로고침 후에는 `GET /api/v1/matches/{match_id}`로 최신 상태를 조회한다.

## 구현 금지선

- 클라이언트 시각만으로 시간초과를 확정하지 않는다.
- 브라우저 종료 감지만으로 즉시 시간초과 처리하지 않는다.
- 네트워크 끊김 감지만으로 즉시 시간초과 처리하지 않는다.
- PvP reconnect/grace rule을 1차 MVP AI 스토리 규칙에 섞지 않는다.
- WebSocket, Redis, heartbeat를 1차 MVP 시간초과 판정 필수 조건으로 만들지 않는다.
