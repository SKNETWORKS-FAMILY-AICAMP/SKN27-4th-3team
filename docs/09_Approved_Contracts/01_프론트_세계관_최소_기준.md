# 프론트 세계관 최소 기준

이 문서는 프론트엔드팀에 공유할 승인된 최소 기준이다.

세부 화면 구성, 상태 시각화, 애니메이션, 문장 배치, UI 스타일은 프론트팀이 자유롭게 설계한다. 이 문서는 프로젝트 정체성에서 벗어나지 않기 위한 최소 금지선만 둔다.

## 역할 경계

오너는 아래 항목의 최종 기준을 정한다.

- 세계관의 큰 틀
- 첫 스토리의 핵심 구조
- 괴이 컨셉, 금기, 진명 조각, 거짓 단서 기준
- API, 폴더 구조, 앱 경계, 인증, 응답 형태 같은 기술 계약

프론트팀은 승인된 기준 안에서 아래 항목을 설계한다.

- 스토리 화면 흐름
- 브리핑, 결투, 결과 화면의 표현과 연출
- 문장 배치와 정보 노출 순서
- 화면 전환, 상호작용, 상태 시각화
- 사용자가 사건을 이해하고 진행하는 UI 경험

프론트팀이 작성한 세부 흐름, 표현, 문장은 오너가 승인하기 전까지 공식 설정, 룰, 서버 판정으로 취급하지 않는다.

LLM/RAG는 별도 담당자가 맡을 수 있다. 단, LLM/RAG 담당자는 승인된 금지선, fallback 기준, 로그 구조, 서버 권위를 지켜야 한다.

API, 인증, DB, 폴더 구조, 앱 경계 같은 기술 계약은 오너 승인 전까지 프론트팀이나 LLM/RAG 담당자가 임의로 고정하지 않는다.

## 큰 톤

`pilot`은 초자연 공포 스릴러 미스터리 기반 1대1 턴제 심리전 웹 게임이다.

플레이어는 괴이를 체력으로 깎아 죽이는 전투자가 아니라, 저주받은 생존자로서 괴이와 마주 앉아 진명을 파헤치고 봉인한다.

핵심 감각은 카드 배틀보다 `생존 의식 테이블`에 가깝다.

## 프론트 자유 범위

프론트팀은 아래 항목을 자유롭게 설계할 수 있다.

- 레이아웃
- 색, 질감, 아이콘, 애니메이션
- 상태를 시각화하는 방식
- 공개 로그의 표시 위치
- 단서 패널의 접기/펼치기
- 브리핑과 결과 화면의 연출
- 모바일/데스크톱 화면 구조

## 최소 금지선

아래 항목은 피한다.

1. 카드 배틀, 스킬 버튼 전투, 판타지 RPG 전투 UI처럼 보이게 만들지 않는다.
2. 가챠, 보상 뽑기, 환금성 재화, 사행성 결제처럼 보이는 표현을 쓰지 않는다.
3. LLM 채팅 게임처럼 보이게 만들지 않는다. 플레이의 중심은 자유 대화가 아니라 서버 판정형 의식 결투다.
4. 프론트가 승패, 수치 변화, 단서 진위, 봉인 가능 여부를 임의로 결정하지 않는다.
5. 서버 응답과 충돌하는 문구를 화면에 표시하지 않는다.
6. 괴이를 체력 게이지로 깎아 죽이는 구조처럼 표현하지 않는다. 목표는 진명을 파헤치고 봉인하는 것이다.
7. 결과 화면에서 LLM 생성 문장이나 프론트 문구를 서버 판정 결과처럼 위장하지 않는다.

## 서버 권위

아래 항목은 반드시 서버 응답을 기준으로 표시한다.

- 현재 이성, 의식력, 저주 흔적
- 행동 비용과 행동 가능 여부
- 턴 결과
- 진명 조각 획득 여부
- 거짓 단서 공개 여부
- 봉인 가능 여부
- 승패

프론트는 임시 애니메이션이나 예측 표시를 사용할 수 있지만, 최종 상태는 서버 응답으로 동기화한다.
