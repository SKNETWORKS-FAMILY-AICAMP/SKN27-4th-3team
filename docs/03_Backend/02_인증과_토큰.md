# 인증과 토큰

## 인증 방식

- Django user model은 `accounts.User` custom user model을 사용한다.
- user model은 `AbstractBaseUser + PermissionsMixin` 기반이다.
- 로그인 식별자는 email이다.
- nickname은 `profiles.Profile`에 저장한다.
- JWT access token + refresh token rotation을 사용한다.
- access token 만료는 15분이다.
- refresh token 만료는 14일이다.
- access token은 JWT다.
- refresh token은 JWT이며 `jti`, `family_id` claim을 포함한다.
- refresh 요청마다 새 refresh token을 발급한다.
- 이전 refresh token은 `rotated` 상태로 전환한다.
- `rotated`, `revoked`, `reused` token 재사용 감지 시 token family 전체를 폐기한다.
- refresh token family id는 로그인 성공 시 UUIDv4로 생성한다.
- refresh token jti는 refresh token 발급마다 UUIDv4로 생성한다.
- refresh token은 원문 저장하지 않고 해시로만 저장한다.
- refresh token hash는 서버 secret 기반 HMAC-SHA256으로 저장한다.
- 토큰은 localStorage/sessionStorage에 저장하지 않는다.
- access token과 refresh token은 모두 HttpOnly cookie로 전달한다.
- access token cookie path는 `/api/v1`이다.
- refresh token cookie path는 `/api/v1/auth/refresh`다.
- 쿠키 SameSite는 `Lax`를 사용한다.
- local/dev 환경에서는 `Secure=false`를 허용한다.
- production 환경에서는 `Secure=true`를 필수로 한다.
- refresh endpoint는 DB transaction과 row lock으로 동시성을 제어한다.
- refresh token reuse grace window는 두지 않는다.

## Refresh Token 저장 필드

| 필드 | 설명 |
|---|---|
| id | 내부 ID |
| user_id | token 소유자 |
| jti | refresh token 고유 식별자 |
| family_id | 로그인 session 계열 ID |
| token_hash | HMAC-SHA256 hash |
| status | `active`, `rotated`, `revoked`, `reused` |
| issued_at | 발급 시각 |
| expires_at | 만료 시각 |
| rotated_at | rotation 시각 |
| revoked_at | 폐기 시각 |
| reused_at | 재사용 감지 시각 |
| replaced_by_jti | rotation 후 새 token jti |

## Refresh Token Reuse 처리

이미 `rotated`, `revoked`, `reused` 상태인 refresh token이 제출되면 아래 순서로 처리한다.

1. refresh 요청을 실패 처리한다.
2. 해당 `family_id`의 모든 refresh token을 revoke한다.
3. access token cookie와 refresh token cookie를 제거한다.
4. security event log를 저장한다.
5. `REFRESH_TOKEN_REUSED` error code로 응답한다.

## CSRF

- 모든 state-changing endpoint에 CSRF를 적용한다.
- CSRF token endpoint는 `GET /api/v1/auth/csrf`다.
- CSRF header 이름은 `X-CSRFToken`이다.
- 로컬 환경에서도 CSRF 흐름을 비활성화하지 않는다.
- 로그인 시 CSRF token을 rotation한다.
- refresh 시 CSRF token은 유지한다.
- logout 후에는 새 `GET /api/v1/auth/csrf`가 필요하다.
- CSRF token은 프론트 memory에만 보관한다.
- `CSRF_TRUSTED_ORIGINS`와 CORS origin은 명시 allowlist만 허용한다.

## Security Event Log

아래 이벤트는 최소 security event log로 남긴다.

- refresh token reuse 감지
- refresh token family revoke
- CSRF 실패
- 로그인 실패 반복
- 권한 없는 match 접근 시도
- participant가 아닌 사용자의 행동 제출 시도

## 구현 금지선

- `csrf_exempt` 사용 금지
- CSRF middleware 비활성화 금지
- dev 환경에서 CSRF 흐름 비활성화 금지
- CORS 전체 허용 금지
- `CSRF_TRUSTED_ORIGINS` 전체 허용 금지
- localStorage/sessionStorage token 저장 금지
- refresh token 원문 저장 금지
- refresh token reuse grace window 금지
- refresh 성공 시 기존 token을 active로 남기는 구현 금지
