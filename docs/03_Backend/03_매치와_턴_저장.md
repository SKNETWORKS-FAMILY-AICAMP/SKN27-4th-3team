# 매치와 턴 저장

## 대상 테이블 초안

| 테이블 | 주요 필드 |
|---|---|
| matches | id, mode, status, winner_participant_id, started_at, ended_at |
| match_participants | id, match_id, participant_type, user_id, apparition_id, side, sanity, ritual_power, curse_marks, secret_exposure |
| turns | id, match_id, turn_number, status, deadline_at, resolved_at |
| action_submissions | id, turn_id, participant_id, action_code, info_target_key, submitted_at, client_nonce |
| turn_results | id, turn_id, result_json, public_log_json, private_log_json, schema_version |

## AI participant 기준

괴이는 Django user가 아니다.

| 필드 | 기준 |
|---|---|
| participant_type | `human` 또는 `apparition` |
| user_id | human 참가자에서만 사용한다. apparition 참가자에서는 nullable이다. |
| apparition_id | apparition 참가자에서 사용한다. human 참가자에서는 nullable이다. |

## AI 스토리 매치 기준

PvP 모드는 없다.

`matches`, `match_participants`, `turns`, `action_submissions`, `turn_results`는 AI 스토리 단일 플레이 기준으로 설계한다.

| 항목 | 기준 |
|---|---|
| matches.mode | 1차 MVP 기준 `ai_story`만 구현한다. |
| winner_participant_id | 승자는 user가 아니라 participant 기준으로 저장한다. |
| match_participants | human player와 apparition을 표현한다. |
| action_submissions | user 기준이 아니라 participant 기준으로 저장한다. |
| client_nonce | participant + turn 범위에서 중복 제출을 막는다. |
| 접근 권한 | 요청 사용자가 해당 match의 human participant인지 확인한다. |

## 금지 가정

- PvP match를 만들지 않는다.
- human vs human participant 구조를 구현하지 않는다.
- WebSocket을 권위 있는 상태 변경 경로로 전제하지 않는다.
- Redis matchmaking, reconnect window를 전제로 두지 않는다.
- AI 스토리 상태 동기화용 WebSocket/Redis는 [[09_Approved_Contracts/29_MVP_Realtime_Redis_WebSocket_계약]] 범위에서만 사용한다.
- `match.user_id`처럼 단일 소유자만으로 접근 권한을 판단하지 않는다.

## MVP 방향

- AI 스토리 단일 매치도 `matches` 구조에 저장한다.
- 결과 계산은 `game_rules`에서 수행하고 `matches`는 저장을 담당한다.
- JSONField는 결과 스냅샷과 로그 스냅샷에만 제한적으로 사용한다.
- JSONField payload에는 `schema_version`을 포함하고 Python `jsonschema`로 검증한다.
- 상세 기준은 [[09_Approved_Contracts/17_백엔드_RAG_AI_Profile_구현_계약]]을 따른다.
- PvP 미사용 기준은 [[09_Approved_Contracts/19_PvP_미사용_및_구조_정리_계약]]을 따른다.
