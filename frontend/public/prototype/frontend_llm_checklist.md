# 프론트/LLM 연동 확인 체크리스트

이 문서는 `frontend_handoff.md`에서 실제 구현 항목을 제외하고, 사람에게 확인받아야 할 항목만 따로 정리한 문서다.

## 프론트 팀원에게 확인받을 것

1. 실제로 사용할 `display_slot` 목록
   - 현재 후보:
     - `left_system_message`
     - `right_apparition_message`
     - `center_system_message`
   - 실제 컴포넌트 이름이나 화면 배치와 맞는지 확인이 필요하다.

2. `turn_flavor_text` 최대 길이
   - 현재 기준:
     - 전체 20-90자
     - 1-2줄
     - 줄당 45자 이하 권장
   - 실제 게임 화면에서 너무 길거나 짧지 않은지 확인이 필요하다.

3. 줄바꿈 처리 방식
   - LLM 응답의 `\n`을 그대로 렌더링할지 확인한다.
   - 현재 prototype은 줄바꿈을 유지하는 방향으로 동작한다.

4. LLM 비활성/실패 시 표시 방식
   - `llm.enabled=false` 또는 `metadata.status="failed"`일 때 LLM 전용 영역을 숨길지 확인한다.
   - 현재 prototype은 같은 위치에 서버 기본 공개 로그 또는 기존 대사를 표시한다.

5. LLM 문구와 공식 결과가 같이 오는 경우의 우선순위
   - LLM 문구는 연출 보조 문장이다.
   - 승패, 수치 변화, 턴 결과, 공개 로그의 공식 판정은 서버/게임 규칙을 우선한다.

6. 로딩 UI 필요 여부
   - LLM 응답을 기다리는 동안 별도 로딩 표시가 필요한지 확인한다.
   - MVP에서는 LLM 실패 시 fallback 문구로 즉시 표시할 수 있어야 한다.

7. 개발 중 디버그 정보 표시 여부
   - `fallback_used`
   - `metadata.error_reason`
   - `metadata.status`
   - 위 정보들을 화면에서 확인할 필요가 있는지 결정한다.

## LLM 팀에 전달해주면 좋은 것

1. 실제 메시지 박스 크기
   - 각 `display_slot`이 차지하는 너비와 높이.
   - 특히 귀신 반응 메시지 영역은 문장이 길면 분위기를 해칠 수 있다.

2. 모바일/데스크톱별 허용 줄 수
   - 데스크톱에서는 1-2줄 가능.
   - 모바일에서는 더 짧은 문장 기준이 필요할 수 있다.

3. `display_slot`별 글자 수 제한
   - 예시:
     - `left_system_message`: 짧은 주인공/시스템 문구
     - `right_apparition_message`: 귀신 반응 문구
     - `center_system_message`: 턴 결과 강조 문구

4. 귀신 반응과 시스템 문구의 시각적 구분 방식
   - 귀신 반응은 붉은색 계열.
   - 시스템 문구는 흰색 또는 회색 계열.
   - LLM 문구가 공식 판정처럼 보이지 않게 해야 한다.

5. 실패 시 보여줄 기본 로그 위치
   - LLM 실패 시 `publicLog.text`를 어느 위치에 보여줄지 공유한다.
   - 현재 prototype은 같은 메시지 위치에 fallback으로 표시한다.

6. 줄바꿈이 자연스럽게 보이는지 여부
   - LLM이 `\n`을 포함해도 화면에서 어색하지 않은지 확인한 뒤 문장 생성 기준에 반영한다.

7. LLM 문장 톤 기준
   - 게임 판정을 직접 말하지 않는다.
   - 수치 변화를 임의로 해석하지 않는다.
   - 분위기, 반응, 짧은 심리 묘사 중심으로 작성한다.
   - 실패해도 정적 문구로 대체 가능한 문장이어야 한다.
